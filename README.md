## Запуск

Нужен Python 3.12. Из корня проекта в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m lab6_app.configure
.\.venv\Scripts\python.exe -m flask --app lab6_app run
```

На Linux и macOS используйте `python3.12` для создания окружения и
`.venv/bin/python` в остальных командах. Откройте [локальную страницу](http://127.0.0.1:5000/).

Команда `configure` запросит имя пользователя и пароль. Она создаст
`instance/config.json` с хешем пароля и случайным ключом сессии. Каталог
`instance/` исключён из Git. Для просмотра общедоступных страниц первый
запуск `configure` можно пропустить.

## Как проверить задания

| Задание | Что открыть и проверить |
| --- | --- |
| Статическая страница и CSS | `/about` отдаёт готовый `static/about.html`. Оформление загружается из `/static/site.css`. |
| Bootstrap | На `/` сетка, таблица, форма и кнопки оформлены классами Bootstrap. CSS загружается с CDN с проверкой целостности. |
| Шаблон Jinja2 | Шаблон `templates/index.html` строит строки из `lab6_app/tasks.py`. Выберите «Повышенная» и нажмите «Показать», чтобы оставить две строки. |
| Авторизация | Откройте `/account` без входа, затем введите свои данные. Неверный пароль оставляет кабинет закрытым. Кнопка «Выйти» завершает сессию. |
| Heroku | Для подтверждения нужен запущенный экземпляр и проверенный HTTPS-адрес. Шаги развёртывания приведены ниже. |

При входе Flask сверяет имя и хеш пароля. После успеха приложение создаёт
подписанную сессию на два часа. Вход и выход выполняются POST-запросами
с CSRF-токеном. На Heroku сессионный cookie передаётся только по HTTPS.
Учебная версия поддерживает одну учётную запись, которую настраивает
владелец приложения.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

Тесты проверяют HTML и CSS, отбор строк по сложности, корректный и
ошибочный вход, закрытый кабинет до входа и после выхода, проверку
CSRF-токена и параметры cookie в режиме Heroku.

## Развёртывание на Heroku

Приложение подготовлено к развёртыванию. В репозитории есть `Procfile`,
`.python-version`, `requirements.txt` и инструкция по настройке Config Vars.
Локально проверены запуск приложения, вход и выход. Все 10 тестов прошли.

Развёртывание на Heroku не выполнено. При регистрации сервис показал
сообщение «We do not accept sign-ups from your country.», поэтому создать
аккаунт и запустить приложение на Heroku не удалось.

1. В [Heroku Dashboard](https://dashboard.heroku.com/apps) создайте
   приложение на верифицированном аккаунте. Для публичного запуска нужен
   активный web dyno на выбранном тарифе.
2. В локальном терминале выполните
   `.\.venv\Scripts\python.exe -m lab6_app.configure --heroku`. Задайте
   отдельные имя и пароль. Скопируйте три значения в **Settings → Config Vars**.
   Имена переменных указаны в таблице ниже. Вставляйте значения после знака
   `=` целиком. Храните их только в настройках приложения.
3. На вкладке **Deploy** подключите GitHub-репозиторий
   `yurtanakatya-cpu/mtp-lab6-variant3` и запустите **Deploy Branch** для
   `main`. Heroku установит зависимости из `requirements.txt` и выберет
   Python 3.12 из `.python-version`. Команда в `Procfile` запускает Gunicorn
   на порту, который назначает Heroku.
4. После успешного билда нажмите **Open app**. Откройте `/healthz` по HTTPS
   и проверьте ответ `{"status":"ok"}`, затем проверьте главную страницу,
   вход в кабинет и выход. Для сдачи добавьте в README подтверждённую ссылку
   на приложение.

| Config Var | Назначение |
| --- | --- |
| `LAB6_USERNAME` | Имя для входа |
| `LAB6_PASSWORD_HASH` | Хеш пароля из команды `configure --heroku` |
| `LAB6_SECRET_KEY` | Случайный ключ подписи cookie |

[GitHub Deploys на Heroku](https://devcenter.heroku.com/articles/github-integration),
[запуск Gunicorn](https://devcenter.heroku.com/articles/python-gunicorn).
